# Agent 数据流水线与召回边界

第一版只使用 `data/archive.json` 中已经审阅的工作摘录、专题、时间节点、研究问题、图表说明和文档摘要。构建不会读取原始群聊导出、`editorial/` 底稿、附件全文、图片、音频或 OCR 结果；也不会调用外部模型或 API。

**这是 agent 专用语料的脱敏，不是对原始聊天和全部公开附件的完整隐私审计。** 现有静态站点的 `data/archive.json`、`data/archive.js` 和 `assets/` 保持原样。本轮没有清理 Git 历史。若今后在现有公开材料中发现真正的凭证或私人信息，需要另外修订原站发布数据及相应历史；仅修改 agent 语料不能撤回已经公开的内容。

## 构建和产物

在仓库根目录运行：

```sh
npm run agent:build
```

产物写入被 Git 忽略的 `.local/agent-release/`，不会被静态站点构建复制到 `dist/`：

- `corpus.json`：脱敏后的节点、共享证据、时间树、主题树和关键词倒排索引。
- `privacy-report.json`：来源 SHA-256、语料版本、数量、规则匹配次数及排除 ID；不记录敏感值。
- `kv-upload.json`：供发布至私有 Cloudflare KV 的批量写入文件，键为 `corpus:<version>`。

语料版本由确定性内容哈希产生，不使用运行时间。相同归档与规则重复构建，三个文件逐字节一致。当前构建为 1,417 个可召回节点、1,110 条共享证据、10 个专题加独立事项分组，以及 80 个月份。19 条仅含附件不可读或脱敏占位的消息保留证据状态，但不作为独立召回节点。

每条证据只投影 `id`、`date`、`text`。不带发送人字段、源文件路径、导出行号、附件 URL 或原始附件。所有投影文本先脱敏，再构建索引；两棵树引用同一组证据 ID。

## 脱敏规则与排除

规则包括凭证格式、Bearer/JWT、私钥、邮箱、手机号、身份证、私人联系信息行、内网地址与链接、URL 用户信息和参数、本地路径，以及已知发送人名称。全角字符和常见零宽字符先规范化。报告中的匹配次数是处理字段的命中次数，可能包括同一来源的多处派生文本，不是独立敏感消息数量。

曾发现一处手机号形态匹配位于 `m02838` 的 Wiley DOI 路径中；核实是学术标识误伤，未改写原站。现在只对有效 DOI 路径豁免手机号启发式；凭证、JWT、邮箱等检查继续执行，URL 参数仍删除。当前 agent 语料构建报告为 12 次 URL 参数清理、66 次作者／私有词清理、5 次私有链接移除；无真实手机号命中。

公共规则在 `agent/privacy-policy.json`。额外私有规则放入忽略的 `.local/agent-privacy.json`，不要把真实私人词表提交到 Git：

```json
{
  "privateTerms": [],
  "excludedEvidenceIds": [],
  "excludedRecordIds": [],
  "topicAliases": {}
}
```

`privateTerms` 支持明确指定的单字；自动发送人匹配只处理两个字及以上，避免单字姓氏破坏普通研究文本。`excludedRecordIds` 可使用完整 ID（如 `question:某项ID`、`evidence:m00001`）或相应的原记录 ID。排除一个记录会排除其直接来源消息；其他引用这些消息的摘要节点也会整体退出语料，避免经另一棵树或派生摘要重新泄漏。仅移除引用 ID 而保留相关摘要正文是不够的。

规则脱敏不能保证发现语义上的私人内容、间接身份线索、未列出的其他人员姓名、无明显格式的账号、私人事件或所有编码混淆。第一版不声称已经完成附件正文或图像审查。发布前应复核拟开放语料；后续导入新记录也须重新检查。

## 时间、主题与证据召回

- 时间树按年份、月份组织，精确日期再筛选；支持中文／ASCII 年份范围、月份范围、单日和 ISO 日期。明确时间范围的回答不会夹带范围外的证据。
- “今年／去年／前年”按语料截止年份解释，并在结果中注明 `relativeToCutoff`；不把过期档案当成实时资料。
- 主题树复用专题标签与可配置别名，支持跨分支召回。当前页面只作为提示，不能让一个没有关键词或主题命中的陌生问题凭空得到答案。
- 项目总览是跨年摘要，当前图表入口也不是历史工作日期；它们不进入某年某月的时间树，避免将迁移链接日期误写为研究进展。
- 状态类问题优先研究问题节点，并保留最后讨论、最后实质进展和材料日期的区别。建议、验收条件继续标为尚待执行。
- 关键词倒排索引用于补召回。召回后按相关性和节点类型排序、去重；全年总览优先历史工作事件并避免同一个月占满结果。
- 直接索取密码、私人联系方式等的问题不进行证据召回。没有足够依据时返回无结果，不据此推断现实中没有完成工作。

`retrieve()` 返回 `trace`，包含 `phase`、中文 `label`、`status: "done"`、安全数量、时间范围、专题标题、入选节点 ID／标题与证据 ID。它不输出原文，也不是模型内部思考内容。前端可将这些事件逐步显示为“解析 → 关键词 → 时间树 → 主题树 → 合并排序 → 证据”流程。

## 验证

```sh
node --test agent/tests/privacy.test.mjs agent/tests/retrieval.test.mjs
```

39 个检查通过，包含 30 个真实档案问题的召回评测、明确日期不越界、别名、最后已知状态、无结果、私人信息请求、对象原型词输入、确定性构建，以及被排除来源不能经证据／摘要／索引重新出现的回归检查。评测定义保存在 `agent/tests/retrieval-eval.json`。这些评测验证检索与数据边界；不等于模型最终回答质量已经通过真实 OpenAI 调用验证。
